# Cafe24 배포 준비

## 현재 상태

사용자가 확정한 단일 차콜·블루 디자인을 포함한 배포 자료입니다. 아직 운영 서버에 업로드하거나 DB를 변경하지 않았습니다. 서버 연결 정보와 운영 백업은 배포 시 준비해야 합니다.

## 배포 파일 만들기

프로젝트 루트에서 `python3 tools/build_release.py`를 실행합니다.

- `release/joyban-web.zip`: FTP로 업로드할 웹 파일. DB 비밀번호, 사용자 업로드, 개발 문서, SQL, 테스트는 제외합니다.
- `release/joyban-setup.zip`: DB 적용 SQL, 관리자 CLI 도구, 설치 안내. 전체를 공개 웹 루트에 올리지 않습니다.

사용하지 않는 이전 히어로 이미지도 웹 패키지에서 제외합니다. `.htaccess` 숨김 파일은 포함됩니다. 배포 자료 자체는 Git에서 제외합니다.

## 기존 운영 사이트 적용 순서

1. Cafe24 또는 SSH에서 운영 DB 덤프를 확보하고, FileZilla로 웹 파일과 `uploads/`를 백업합니다. 백업은 공개 웹 루트 밖에 보관합니다.
2. FileZilla의 실제 웹 루트 위치를 확인합니다. 도메인의 현재 `index.html`과 `api/`가 있는 위치에 업로드합니다.
3. 유지보수 시간을 확보하고 기존 DB에 `sql/migrate-portal.sql`을 적용합니다. DB 접속은 비밀번호를 명령줄에 쓰지 않는 `mysql -u <DB사용자> -p webmanizu` 형태로 진행합니다. SQL을 적용할 수 있는 실제 DB 접속 경로는 호스팅 설정에서 확인합니다.
4. 기존 게시글 카테고리가 `ailand`, `job`, `profile`일 때만 `migrate-categories.sql`을 검토해 별도로 적용합니다. 기존 운영 DB에 `schema.sql`을 실행하지 않습니다.
5. 기존 `api/config/db.php`를 보존합니다. 기존 관리자 비밀번호가 평문이면 새 로그인 코드 적용 전 CLI 도구로 해시 비밀번호를 설정합니다. `api/config/connect.php`가 필요한 도구이므로 해당 파일과 도구를 먼저 함께 준비할 수 있습니다.
6. `joyban-web.zip`을 로컬에서 풀어 그 안의 파일을 FTP 업로드합니다. `uploads/`의 기존 파일은 삭제하지 않습니다. 루트 `.htaccess`와 `uploads/.htaccess`도 반영합니다.
7. 운영에 남은 `api/hash_gen.php`는 삭제합니다. 새 패키지는 해당 파일을 포함하지 않습니다.
8. DB 비밀번호를 교체하고 운영 `db.php`를 맞춥니다. 관리자 CLI 도구를 필요 시 서버의 `tools/`에 별도 올린 후 SSH에서 `php tools/admin_password.php`를 실행합니다. 계정 설정 후 도구를 제거해도 됩니다.
9. PHP PDO MySQL·fileinfo, HTTPS, 운영 오류 표시 설정과 업로드 제한을 확인합니다.
10. 아래 운영 확인을 진행합니다. FTP 배포 후 오래된 CSS·JS가 보이면 브라우저에서 강력 새로고침합니다.

SQL과 인증 코드는 같은 배포에서 적용해야 합니다. FileZilla로 파일 일부가 교체되는 동안에는 기능이 일시적으로 맞지 않을 수 있습니다.

## 운영 확인 목록

- [ ] HTTPS 메인 화면, AI봇, 상단 블루 → 하단 차콜 배경 표시
- [ ] PC와 모바일에서 제목·검색·메뉴가 겹치지 않음
- [ ] 공개 자료 조회, 분야·태그·검색 필터
- [ ] 관리자 로그인과 로그아웃
- [ ] 비공개 링크 저장 후 로그아웃 시 미노출
- [ ] 공개 링크 저장·수정·삭제
- [ ] 즐겨찾기·읽음 상태 변경
- [ ] 기존 게시글 조회·작성·수정·첨부·삭제
- [ ] `/api/config/db.php`, `/sql/schema.sql`, `/AGENT.md` 접근 차단
- [ ] 오류 응답에 DB 접속 정보와 서버 상세 오류가 노출되지 않음

## 되돌리기

문제가 있으면 백업의 웹 파일을 인증·API·JS 포함 동일 버전으로 복원합니다. 배포 후 새 자료가 있다면 DB·업로드 백업을 무조건 덮어쓰지 않습니다. 추가한 포털 테이블은 자료 보존을 위해 유지할 수 있습니다. 상세 복구 주의사항은 `docs/personal-portal.md`를 참고합니다.
